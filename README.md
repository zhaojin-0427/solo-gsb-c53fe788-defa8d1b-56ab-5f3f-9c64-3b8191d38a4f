# 供水检修隔离方案台

在画布上维护供水管网（水源、用水节点、管段、阀门），选择待检修管段与必须保供的节点，
一键求解**关闭哪些阀门**的方案：既要把检修段两端与所有水源隔离，又要保证保供节点不断水，
并按「断供户数 → 关阀数量 → 阀门 ID 升序列表」的字典序做到最优。

- 后端：Python + FastAPI + SQLite + OR-Tools（CP-SAT）
- 前端：原生 JavaScript 画布（无任何前端框架 / 构建步骤）
- 部署：Docker Compose 一键启动

## 快速开始

```bash
docker compose up --build
```

启动后访问 **http://localhost:8000** 。

- 场景与求解方案持久化在命名卷 `water_data`（容器内 `/data/app.db`）中，
  浏览器刷新、容器重启后仍可查看场景与对应方案。
- 停止：`docker compose down`；连数据一起删除：`docker compose down -v`。

### 本地开发（不用 Docker）

```bash
pip install -r requirements.txt
uvicorn app.main:app --reload --port 8000
# 打开 http://localhost:8000
```


## 使用说明

1. **搭建管网**：工具栏选择「＋水源 / ＋用水节点」点击画布放置；「＋管段」依次点击两个节点连线；
   「选择 / 移动」可拖动节点、点选对象；「删除」点击移除。
2. **编辑属性**：选中节点可改 ID、类型、户数（非负整数）、是否**必须保供**；
   选中管段可改 ID、是否**可关闭阀门**、是否**待检修管段**（橙色虚线）。
3. **保存场景**：右侧面板命名并保存；非法管网（端点不存在、ID 重复、超上限等）会被拒绝并提示原因。
4. **求解**：点击「保存并求解」（预算 10 秒）。画布随即着色：
   绿色＝供水节点，红色＝断供节点，蓝色＝水源，红色叉形菱形＝已关闭阀门。
5. **查看方案**：右下「方案」面板给出状态、断供户数、关阀清单、供/断供节点与耗时；
   刷新页面后自动恢复上次场景与最新方案。

首次打开（无任何已存场景）会自动载入一个示例管网，并预选好检修段与保供节点，可直接点「保存并求解」体验。

## 判定与求解语义

关闭阀门、移除检修段后，按剩余管段的**真实连通性**判定：

- 检修段两端节点不得接通任何水源（隔离要求）；
- 每个保供节点必须接通至少一个水源；
- 与任何水源都不连通的孤岛一律记为断供，**不计为供水**（其户数计入断供户数）。

优化目标按字典序依次最小化：

1. **断供总户数**（所有未接通水源节点的户数之和）；
2. **关闭阀门数量**（检修段本身即使带阀也不计入）；
3. **关闭阀门 ID 升序列表**的字典序（ID 按自然序比较：数字段按数值，如 `E2 < E10`）。

求解预算 10 秒，结果状态：

| 状态 | 含义 |
|---|---|
| 最优（已证明） | 10 秒内找到并证明了字典序最优解 |
| 可行（未证明最优） | 超时，但手头有满足全部约束的方案，予以展示 |
| 未找到可行解 | 超时且没有任何可行解（未证明不可行） |
| 无解（已证明不可行） | 已证明不存在满足约束的关阀方案，只有此时才报无解 |

求解器用 CP-SAT 建模：每个节点的「是否接通水源」由流向约束（可达⇒连通）与
沿未关管段的传播约束（连通⇒可达）共同锁定，再分三个阶段依次固定前一级目标值求解，
保证字典序；最终方案还会用 BFS 真实连通性复核后再展示。

## 数据与限制

- 节点 ≤ 80，管段 ≤ 120（无向），可关闭阀门 ≤ 40；
- 户数为非负整数（≤ 10¹²）；水源户数恒为 0；
- 节点 / 管段 ID 为非空字符串（≤ 64 字符），各自唯一；管段两端必须存在且不允许自环；
- 阀门 ID 即其所在管段的 ID；
- 违反上述规则的管网在保存时即被拒绝（HTTP 422），不会入库。

## API 概览

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/scenarios` | 场景列表 |
| POST | `/api/scenarios` | 新建场景（校验管网） |
| GET | `/api/scenarios/{id}` | 场景详情 + 最新方案 |
| PUT | `/api/scenarios/{id}` | 更新场景（结构变化时旧方案作废） |
| DELETE | `/api/scenarios/{id}` | 删除场景及其方案 |
| POST | `/api/scenarios/{id}/solve` | 求解并保存方案，请求体：`{"repair_edge_id": "...", "must_supply": ["..."]}` |

交互式 API 文档：启动后访问 http://localhost:8000/docs 。
